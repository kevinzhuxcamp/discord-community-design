1 Positioning

X-Camp's Discord server is the official X-Camp Learning Hub — not a gaming server. It is introduced to students and parents as a structured, moderated academic community. Discord is the underlying technology; the product is the X-Camp community.

All parent and student-facing communications should refer to it as the "X-Camp Student Hub" or "X-Camp Online Learning Community."

GoalHow the server serves it
Academic Q&AClass Q&A channels, HW Night queue, solved answers archive
Real-time supportHW Night voice rooms (5–8 PM PT daily), office hours 1-on-1
Student bondingCommunity channels, voice study halls, contests, leaderboards
Staff coordinationPrivate staff channels, TA scheduling, mod log
Long-term communityAlumni network, public-facing discovery for CS500+ levels

4 Homework night workflow

Runs daily during the quarter, 5–8 PM PT. A bot-assisted queue ensures fair TA assignment and builds a searchable resolved-answers archive over time.

1
Bot opens HW Night
At 4:55 PM, bot auto-posts in #hw-night-lobby: "HW Night starts in 5 minutes — TAs are online!" Voice rooms unlock.
automated
2
Student posts question
Student uses !question or posts in #ask-a-question with level tag e.g. [CS200]. Bot timestamps, queues, and adds a ticket emoji.
student
3
TA claims question
TA reacts with hand emoji or uses !claim. Bot notifies student. If voice is needed, student is moved to an available HW Night Room.
TA action
4
Question resolved
TA uses !solved. Bot archives thread to #solved-answers. Student rates helpfulness 1–5 stars. Answer stays permanently searchable.
TA closes
5
Bot closes HW Night
At 8:00 PM, bot posts nightly summary: questions answered, avg response time, students helped. Voice rooms lock. Unanswered questions flagged for teacher review.
auto-summary
📋 Queue rules
One active question per student at a time. Questions must include the problem name and what the student already tried. Duplicate questions are linked to existing resolved threads.
👥 TA coverage model
Each level group (100s, 200s, 300s, 400s, 500s+) has at least one TA on duty per HW Night. Coordinator monitors queue depth and can assign additional TAs if wait time exceeds 10 minutes.

5 Office hours workflow

Scheduled 1-on-1 TA support sessions, bookable by students within their level band.

1
Student books a slot
Student uses !officehours or checks the pinned schedule in their class channel. Bot shows available TA slots for that level.
2
Bot sends reminder
10 minutes before the slot, bot DMs both student and TA. Student is prompted to describe their question in advance so the TA can prepare.
automated
3
Session in voice
Student joins the 1-on-1 TA Room. TA can screen share, walk through code, and use the whiteboard. Default session cap is 20 minutes.
TA + student
4
TA posts summary (optional)
After the session, TA may post a brief summary to #solved-answers with the student's permission, contributing to the class knowledge base.
optional log

9 Launch timeline

Weeks 1–2
Foundation
Build server structure, all categories, channels, and roles · Configure permission matrix · Install and configure bots · Write rules and welcome message · Internal staff dry run and feedback session
Week 3
Staff onboarding
Onboard all teachers, TAs, and coordinators · Assign roles and class category ownership · Run mock HW Night with staff only · Finalize moderation and escalation procedures
Week 4
Soft launch — pilot class
Invite one pilot class (recommended: CS300) · Send parent communication letter and consent form · Gather student and parent feedback · Iterate before full rollout
Weeks 5–6
Full rollout
Invite all students by level band · Each teacher hosts first voice session · Launch first Problem of the Week contest · Activate XP system and leaderboard
Month 2+
Community growth
Activate alumni channel · Consider public server discovery for CS500+ · Monthly server health review via Statbot · Iterate channel structure based on usage data
